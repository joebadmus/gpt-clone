SA-1128

It follows on from SA-1117. The pipelines now deploy by digest, but Terraform still names images as <project>/<repo>/<image>:latest, and the triggers use their own repo names.
The work is checking every service's Terraform image path against its trigger's _GAR_IMAGE and _GAR_RELEASES_REPO settings, then fixing any that don't match.
You now have console access to the triggers, so you don't need anyone else for this.
It isn't tiny, because it covers several services, but it's a self-contained audit and fix.


Ways to test it.

1. **Terraform plan:** it should show "No changes" in each environment. Cloud Run ignores image changes made by Terraform, so fixing the paths shouldn't recreate anything.
2. **Pipeline run:** trigger a deploy and check it pushes to and pulls from the repo that Terraform names.
3. **Running service:** for each service, run `gcloud run services describe` and check the image comes from the same repo that Terraform and the pipeline point to.

The plan alone won't catch a wrong path, because Terraform ignores the image. Checks 2 and 3 are the real proof.

**SA-1128: Align Artifact Registry repos and tags between Terraform and CI/CD across all services**

**Description**
Some image paths in Terraform pointed at the wrong repo or image name. They didn't match where the pipelines push images, so it was unclear which image a service should run. This ticket corrects them so Terraform matches what's actually deployed.

**Acceptance criteria**
- In sandbox and dev, the SAYT UI points at the `sayt-ui` repo.
- In dev and pre-prod, the SIC test config image uses `sic-classification-vector-store`.
- The pre-prod UI images use the region variable instead of a hard-coded region.
- The plan shows no service changes. The only change in dev and pre-prod is an update to the test config.
