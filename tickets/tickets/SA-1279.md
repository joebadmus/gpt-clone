# SA-1279: Load testing: size pre-prod like the public test for the final run

**Epic:** SA-962 (load testing)
**Suggested labels:** SAYT public test
**Assignee:** Joe
**Depends on:** SA-1278 (recommended settings), cost sign-off from Matt
**Related:** SA-1266 (pre-prod GKE maintenance exclusion), SA-1275, SA-1276

## Description

The final load test has to run in pre-prod with the settings we expect for the public test. That's the only way to be sure the public environment will cope. Pre-prod may currently be smaller than that, and scaling it up costs more, so the settings and cost need agreeing first.

This ticket agrees the public test settings, applies them to pre-prod, and gets everything the final run needs (SA-1280) in place.

## Starting point: last year's pilot settings

The pre-prod config (`ons-survey-assist-preprod/config.preprod.auto.tfvars`) has last year's pilot settings as comments. The pilot used the `public-beta-test` domain.

| Service | Pre-prod now | Last year's pilot |
|---|---|---|
| SAYT UI | min 1, max 1 | min 10, max 20 |
| Survey Assist API | min 1, max 1 | min 5, max 5 |
| SIC vector store | 1 instance, 1 CPU | 4 instances, 2 CPU |
| OTP service | min 1, max 1 | min 5, max 35 |
| SAYT vector store (GKE) | 1 replica, HPA 1 to 2 | New this year, size from the SA-1277 tests |

Use these as the baseline, then adjust from the sandbox results. For the GKE vector store, consider min 2 replicas so losing a pod doesn't cause an outage. If max replicas goes up, check the regional C4 CPU quota (8 vCPU per pod).

## Approach

1. Agree the expected public test settings with Matt and Steve, starting from the SA-1278 recommendations: Cloud Run min/max instances, concurrency, CPU and memory, and vector store sizing.
2. Estimate the extra pre-prod cost for the test period, and get sign-off from Matt.
3. Apply the settings to `ons-survey-assist-preprod` through a Terraform PR, and update the changelog.
4. Make sure the supporting pieces are in pre-prod:
   - the dashboard from SA-1275
   - the Cloud Armor allow-list and access codes from SA-1276
   - the GKE maintenance exclusion from SA-1266
5. Agree whether pre-prod stays at this size for the public test, or scales back down after the final run.

## Things to be aware of

- Time this with manual testing, so the change doesn't disrupt testers. Check with Steve.
- The UI pipeline triggers are off in pre-prod during testing. Make sure the Terraform change doesn't redeploy different app versions from those on the version tracker page.

## Definition of done

- [ ] Public test settings agreed with Matt and Steve
- [ ] Cost estimated and signed off
- [ ] Pre-prod updated through a reviewed Terraform PR, with the changelog updated
- [ ] Dashboard, Cloud Armor allow-list, access codes and GKE exclusion in place in pre-prod
- [ ] Scale-back plan agreed and noted
