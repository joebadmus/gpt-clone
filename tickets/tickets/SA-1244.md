# SA-1244: Set up a maintenance exclusion for the public test

## Description

The GKE clusters have a daily maintenance window at 2am for 4 hours. In that window Google can upgrade the control plane and the nodes. A node upgrade recreates the SAYT pods, and each new pod pulls an 8 GB image and downloads the embedding model when it starts. If that happens during the public test, suggestions could slow down or fail.

A maintenance exclusion tells Google not to upgrade the cluster between two dates. This ticket adds an optional exclusion to the GKE module, defaulting to none, and sets it in preprod for the length of the public test.

**Where it lives**

- `modules/vector-store-gke/main.tf`: the `maintenance_policy` block on the cluster, which only has `daily_maintenance_window` today
- `modules/vector-store-gke/variables.tf`: new variable for the exclusions
- `ons-survey-assist-preprod/vector-stores.tf`: set the exclusion for preprod
- Sandbox and NatCen also use the module but stay unchanged, because the default is no exclusion

## Approach

1. **Add a variable to the module.** A list of exclusions, each with a name, start time, end time and scope, defaulting to an empty list. Times use RFC 3339, for example `2026-12-01T00:00:00Z`.
2. **Add a dynamic `maintenance_exclusion` block** inside `maintenance_policy`, one per item in the list, with `exclusion_options { scope = ... }`.
3. **Validate the scope** so only `NO_UPGRADES`, `NO_MINOR_UPGRADES` or `NO_MINOR_OR_NODE_UPGRADES` are accepted.
4. **Set it in preprod** with the public test dates.
5. **Update the module README** (terraform-docs) and the preprod changelog.
6. **Plan sandbox and preprod.** Sandbox should show no changes. Preprod should show one in-place change to the cluster, adding the exclusion.

Example of how preprod would set it:

```hcl
gke_maintenance_exclusions = [
  {
    name       = "public-test"
    start_time = "2026-12-01T00:00:00Z"
    end_time   = "2026-12-21T00:00:00Z"
    scope      = "NO_MINOR_OR_NODE_UPGRADES"
  }
]
```

## Which scope to use

| Scope | What it blocks | Longest it can run |
|---|---|---|
| `NO_UPGRADES` | All upgrades, control plane and nodes | 30 days |
| `NO_MINOR_UPGRADES` | Minor version upgrades. Patches and node upgrades still happen. | Until the minor version's end of support |
| `NO_MINOR_OR_NODE_UPGRADES` | Minor upgrades and node upgrades. Control plane patches still happen. | Until the minor version's end of support |

Suggested: `NO_MINOR_OR_NODE_UPGRADES`. It stops the node upgrades that would restart the pods, and it isn't limited to 30 days if the public test runs long. Use `NO_UPGRADES` only if the test is 30 days or less and we want nothing to change at all. Check Google's GKE maintenance exclusion docs for Autopilot before settling, because the limits can change.

## Things to be aware of

- Google can still apply urgent security fixes during an exclusion.
- The exclusion is an in-place change to the cluster. It doesn't recreate anything.
- If the public test dates move, update the dates in preprod and apply again.
- Remove the exclusion once the public test is over, so the cluster gets upgrades again.
- Preprod applies through the pipeline after merge to main.

## Needed from others

- The public test start and end dates. Placeholder dates are fine while building and planning.
