# SA-1266: Set preprod GKE maintenance exclusion for the public test

**Suggested labels:** SAYT public test
**Depends on:** SA-1244 (adds the exclusion option to the GKE module and tests it in sandbox)

## Description

SA-1244 added an optional maintenance exclusion to the GKE module and tried it in sandbox. Preprod doesn't have one yet, because the public test dates aren't agreed.

Without an exclusion, Google can upgrade the preprod cluster in its daily 2am window. A node upgrade restarts the SAYT pods, and each new pod has to pull a large image and download the embedding model before it can serve. That could slow down or break search-as-you-type during the public test.

This ticket sets the preprod exclusion to cover the public test, as part of the final test preparations.

## Approach

1. Get the confirmed public test start and end dates. Check whether December's load testing also needs a stable cluster.
2. In `ons-survey-assist-preprod/vector-stores.tf`, set `gke_maintenance_exclusions` on the `vector-store-gke` module. Add a day either side of the test, and use the scope that worked in sandbox (`NO_MINOR_OR_NODE_UPGRADES`).
3. Update the preprod changelog.
4. Raise a PR. The preprod plan check should show one in-place change to the cluster, adding the exclusion.
5. Merge. The pipeline applies it to preprod.
6. Check the exclusion shows in the GKE console (Cluster details, Maintenance exclusions).

Example:

```hcl
gke_maintenance_exclusions = [
  {
    name       = "public-test"
    start_time = "<START>T00:00:00Z"
    end_time   = "<END>T00:00:00Z"
    scope      = "NO_MINOR_OR_NODE_UPGRADES"
  }
]
```

## Things to be aware of

- `NO_UPGRADES` would block everything but is capped at 30 days. `NO_MINOR_OR_NODE_UPGRADES` can run longer and still stops the node upgrades that restart the pods.
- Google can still apply urgent security fixes during an exclusion.
- If the test dates move, update the dates and apply again.
- Remove the exclusion after the public test, so preprod gets upgrades again.

## Definition of done

- [ ] Public test dates confirmed
- [ ] Preprod exclusion set to cover the test, with a day either side
- [ ] Preprod plan shows only the expected in-place change
- [ ] Applied through the pipeline, and visible in the GKE console
- [ ] Changelog updated
- [ ] A follow-up noted to remove the exclusion after the test
