
**Title:** Make the Vertex AI region configurable per environment in Terraform

**User story**
As a DevOps engineer, I want to set the Vertex AI region for the Survey Assist API in each environment's Terraform, so that we can choose where Gemini requests go without changing the app or setting it by hand in Cloud Run.

**Description**
The API can now read a `VERTEX_AI_LOCATION` env var to choose the Vertex AI region for Gemini, for both SIC and SOC (SA-1165). This ticket adds the Terraform side, so each environment can set it in code.

It follows the same pattern as the Gemini model name (SA-1166):
- A new optional `vertex_ai_location` variable in the `survey-assist-api` module, defaulting to null.
- The `VERTEX_AI_LOCATION` env var is only added to Cloud Run when an environment sets a value.
- If no value is set, nothing changes and the API stays on europe-west2.

This is separate from the Cloud Run region. It only controls where Gemini requests are sent.

**Acceptance criteria**
- The `survey-assist-api` module has an optional `vertex_ai_location` variable, defaulting to null.
- When it's set, Cloud Run gets a `VERTEX_AI_LOCATION` env var with that value.
- When it isn't set, no env var is added, and plans for sandbox, dev and preprod show no changes from this work.
- The module README lists the new input.
- `terraform fmt` and `terraform validate` pass for sandbox, dev and preprod.

**Dependencies**
- The API change (SA-1165) needs to be merged and deployed before setting a value has any effect.
- This builds on the Gemini model name change (SA-1166), as both touch the same lines.

**Out of scope**
- Picking a region for any environment. That can be a one-line change later, once it's needed.
