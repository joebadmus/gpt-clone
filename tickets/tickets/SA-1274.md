## Update after the call with Geoff, 23 November

Full notes in `meeting/2311-LoadTestsummery.md`.

- **The suite:** it's in the load test repo, in a search-as-you-type package next to last year's legacy suite. Geoff's two PRs are with Steve and Matt, and he expects them to merge in a day or two. Setup steps are in the README.
- **How it runs:** by hand, from a laptop on the VPN. There are no plans to automate it. You can change the users, ramp-up, host, run time, think time (last year 12 to 30 seconds), the pause between searches, and the number of searches per question (1 to 5).
- **The journey:** one fixed journey, the paid employee route plus the most complicated feedback path. Each user loops with a new access code until the time limit.
- **No Gemini.** Search-as-you-type is semantic search against the vector store only, so step 6 is answered: there are no LLM calls, quota or cost.
- **Where Locust runs from (step 5):** Geoff ran it against sandbox from his laptop on the VPN with no Cloud Armor exceptions. That's fine for sandbox. Latency measured this way includes the VPN, so use the server-side numbers as the source of truth.
- **Likely bottleneck:** the auto-suggest call (UI to API to vector store), and the calls that save answers through the API.
- **Known risk:** Redis allows 32 concurrent connections per container, and we're aiming for 50 users.
- **Last year:** sandbox, stepping up through 3, 15 and 30 users, about 10 minutes each. The results package and dashboards are on Confluence.
- **Last year's pilot settings** are in the pre-prod config as comments (`# pilot: 10`): UI 10 to 20 instances, API 5, OTP service 5 to 35. Sandbox has 1 of each today. These are likely the "PFR level" mentioned at stand-up.
- **Next:** a baseline run together (about 5 users) once the PRs merge. Then a call this week with Steve, Matt, Ethan and Dan to agree the parameters. Geoff is drafting them on Confluence. First real sandbox run on 25 November, 26 at the latest (SA-1277).
- **Still to confirm:** whether the benchmark is 25 *concurrent* users, how long each run should be, and who does acceptance testing in sandbox.

## Approach

1. Geoff gathers last year's material into one place: dashboards, results, Confluence pages and the Locust docs from SA-1143.
2. Hold a walkthrough session covering the Locust suite, how to run it, the CSV of access codes, and how to read the output.
3. Agree the test scenarios:
   - **Realistic:** about 50 concurrent users with realistic think times. 50 is the record figure. Steve's minimum benchmark is 25 concurrent users.
   - **Stress:** think time set to zero, ramping up until latency or errors break the limits.
4. Agree pass/fail limits with Matt and Steve, for example p95 latency per page and the maximum error rate at 25 and 50 users.
5. Agree where Locust runs from (a laptop, a VM or Cloud Run) and what IP its traffic comes from. Check one machine can drive 50 or more users.
6. Confirm whether the journey calls Vertex AI or Gemini, and roughly how many calls each survey makes. This affects cost and quota (see SA-1276).
7. Confirm the environment order Matt agreed:
   1. Sandbox exactly as it is now.
   2. Tune and repeat.
   3. Final run in pre-prod with production settings.
8. Write it all up on the load testing Confluence page, using the run template from SA-1143 if it's ready.
