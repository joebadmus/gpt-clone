SA-1126: Fix - remove the two-stage API Gateway bootstrap dependency in Terraform
Description
A new environment can't be brought up with one Terraform apply. The API Gateway needs two applies plus a manual step, which Dan hit when setting up NatCen.

Why it happens

The API spec uses the gateway's own hostname in two places, as the host and as the JWT audience (x-google-audiences). GCP only creates that hostname when the gateway is created, so Terraform can't know it up front. Today it's hard-coded per environment in services.tf, for example in dev:

api_gateway_hostname = "survey-assist-api-gw-4zv639tc.nw.gateway.dev"

So a new environment goes like this:

First apply creates the gateway with a config built from a placeholder hostname.
Someone reads the real hostname, puts it in services.tf, bumps api_gateway_spec_version and applies again.
The gateway has ignore_changes = [api_config], so Terraform doesn't switch it to the new config. Someone does that by hand.
Note: we originally logged this as a hard-coded backend URL. That part is fine, the Cloud Run URL already comes from Terraform. The hard-coded value is the gateway hostname.

Where it lives

modules/survey-assist-api/main.tf: locals.config.api_gw_url, and the ignore_changes on google_api_gateway_gateway.api
modules/survey-assist-api/survey-assist-api.yaml: host and x-google-audiences
api_gateway_hostname in each environment's services.tf
Options
Option	What it means	Trade-off
A. Fixed JWT audience	Use a fixed audience (for example survey-assist-api) instead of the gateway hostname, and drop host from the spec	Clean, one apply. But anything that mints tokens needs the new audience: the UIs, smoke tests and NatCen. Breaking change, so not during NatCen testing.
B. Switch the gateway in Terraform	Keep the hostname, and add a step after the gateway exists that builds a second config from the real hostname and points the gateway at it	No client changes, but adds a scripted step to Terraform
C. Document it	Leave as is and keep it in the NatCen manual steps runbook	No code change, the manual step stays
Recommendation: A, after NatCen testing, agreed with Dan and Ethan first.

Definition of done
[ ] Approach agreed with Dan and Ethan
[ ] A new environment comes up with one apply, with no hostname edit or manual config switch
[ ] Existing environments plan with only the expected gateway config change, tested in sandbox first
[ ] If the audience changes: UIs, smoke tests and NatCen updated, and NatCen told in advance
[ ] Gateway step removed from the NatCen runbook
[ ] Changelogs updated
