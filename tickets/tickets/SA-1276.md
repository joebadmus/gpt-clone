## Description

The Locust suite needs to reach the SAYT UI, log in with access codes and run full journeys at volume. Without some preparation, the tests could be blocked, throttled or disrupt other people. This ticket gets sandbox ready for the practice runs, and pre-prod ready for the final run.

## Approach

**Network and Cloud Armor**
1. Add the Locust machine's IP to the Cloud Armor allow-list in sandbox, and later pre-prod, through Terraform.
2. Check the Cloud Armor policy for rate limiting, rate-based bans or bot rules that would throttle many requests from one IP. Agree a temporary exception for the test IP if needed.

**Access codes**
1. Work out how many codes each run needs: users × journeys per user × runs, plus a margin.
2. Agree with Steph or Charlie how to get a **separate batch of codes for Locust**. Generating a new set wipes the existing one, so in pre-prod this mustn't wipe the codes the manual testers are using.
3. Produce the CSV in the format the Locust suite expects.
4. Check the code expiry and the OTP cleanup job (it runs every 5 minutes) won't remove codes partway through a run.

**LLM cost and quota**
1. If the journey calls Vertex AI or Gemini, estimate the calls and cost per run.
2. Check the project quota covers the stress run. Ask for an increase if not.

**Runner and comms**
1. Check the Locust machine can produce the target load. Use Locust's distributed mode if one machine can't.
2. Agree run windows and let sandbox users know. Warn anyone who receives alerts before each run.

## Things to be aware of

- Remove the temporary Cloud Armor allow-list entry and any exceptions after testing (covered in SA-1280).
- Pre-prod prep should wait until manual testing is close to finishing, so it doesn't affect testers.
