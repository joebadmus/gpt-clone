# SA-1235: Set up a log analytics bucket for NatCen

## Description

Sandbox, dev and preprod each have a log analytics bucket for SAYT. A log sink copies the SAYT-related logs into it, so we can query them with Log Analytics (SQL) and keep them longer than the default. NatCen (`survey-assist-sandbox-external`) doesn't have one yet, so NatCen's SAYT logs only sit in the default bucket.

This ticket adds the same bucket and sink to NatCen using the existing `log-analytics-bucket` module. No new module is needed.

**Where it lives**

- `modules/log-analytics-bucket`: the existing module (a bucket with analytics turned on, plus a log sink with optional exclusions)
- New file `survey-assist-sandbox-external/logging.tf`: the module call and filters, copied from dev

**Why copy dev and not preprod**

NatCen runs the SAYT vector store on Cloud Run, like dev. The GKE cluster is commented out in NatCen. So the filter should match the Cloud Run service (`configuration_name="sayt-vector-store"`), not the GKE container, and there's no GKE network policy log to include.

## What the sink collects

- SAYT vector store (Cloud Run)
- Firestore OTP API
- Survey Assist API
- SAYT UI
- API Gateway calls to `/v1/survey-assist/suggestions`
- Load balancer requests that went through the `sandbox-external` Cloud Armor policy

It excludes health checks, meaning Cloud Run `GET /` requests and the OTP health check log line.

## Approach

1. Create `survey-assist-sandbox-external/logging.tf` with the `include_filter` and `exclude_filter` locals from dev, and a `logging-sayt` module call.
2. Set the retention. Dev uses 60 days, and sandbox and preprod use 120. Agree the NatCen value with Dan.
3. Update the NatCen changelog.
4. Run `terraform plan` in `survey-assist-sandbox-external`. Expect 2 to add (the bucket and the sink) and nothing else.
5. **Don't apply yet.** NatCen applies wait until NatCen testing finishes. It goes in with the NatCen apply.
6. After the apply, check the bucket shows in Logging, Log Storage, and run a quick query in Log Analytics to confirm logs are arriving.

## Things to be aware of

- Turning on analytics for a log bucket can't be undone. That's the same as the other environments.
- Log storage beyond the default 30 days is charged. NatCen traffic is low, so the cost should be small.
- The sink uses its own writer identity (`unique_writer_identity = true`). The bucket is in the same project, so no extra IAM is needed.
- The bucket ID is `<project_id>-sayt`. It must not already exist in the NatCen project, or the apply fails.
