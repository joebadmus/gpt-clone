## Approach

1. **Baseline run.** Use a small load (for example 5 to 10 users with realistic think time) to prove the full process works: Locust runs, codes are used, the dashboard shows the traffic, and results are saved.
2. **Realistic run.** Ramp to 25 concurrent users (Steve's benchmark), then 50 (the record figure), with realistic think times. Hold each level long enough to see a steady state.
3. **Stress run.** Set think time to zero and ramp up users until latency or errors pass the agreed limits, to find the breaking point.
4. For each run, record the following in the SA-1143 template:
   - Locust settings: users, spawn rate, duration and think time
   - The app versions and sandbox settings
   - The Locust HTML and CSV reports
   - Dashboard screenshots: latency, errors, instance counts, CPU and memory
   - Which component slowed down or failed first, and any errors seen
   - How many codes were used
5. Review the results with Geoff, and agree what to tune in SA-1278.

## Things to be aware of

- Each run uses up access codes. Check there are enough before starting.
- Note the sandbox settings used, so later runs can be compared fairly.
