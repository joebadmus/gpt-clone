# SA-1127: Fix - separate Themes Flask secret key per environment

## Description

The Themes UI reads its Flask secret key from a secret called `themes_flask_secret_key` in each project. Terraform only points at it. The secret itself was created by hand, so we can't easily see or prove whether each environment has its own value.

At the infra sync on 27 Oct we agreed that Flask keys should be:

- separate for each project, so access to one environment's key doesn't give access to the others
- generated by Terraform, not made by hand
- never regenerated on plan or apply, because a new key logs every user out
- rotated only on purpose, by a documented manual step

This ticket does that for the Themes UI in every environment. Matt asked for it as its own PR. Once it's done, the same pattern can be used for the main UI, SAYT and Genie keys.

**Where it lives**

- Themes UI `FLASK_SECRET_KEY` in each environment's `ui.tf` (sandbox, sandbox-external, dev, preprod)
- `modules/cloud-run-ui`, which injects the secret into Cloud Run

## Approach

1. **Check what's there now.** Compare a hash of the current Themes key in each project (never the value itself) to see whether any are shared.
2. **Generate the key in Terraform.** For each environment: a `random_password`, a Secret Manager secret with the same europe-west2 replication as today, and a secret version. Add the `hashicorp/random` provider and update the lock files.
3. **Stop it regenerating.** The password only changes when a `rotation` keeper value is changed on purpose.
4. **Switch Themes over.** Point the Themes UI at the new Terraform-managed secret. Once every environment has moved, delete the old hand-made `themes_flask_secret_key`.
5. **Document rotation.** Bump the keeper, apply, and expect Themes users to be logged out once.

**Things to be aware of**

- Switching keys logs Themes users out once in each environment. Do it at a quiet time.
- A Terraform-generated value is stored in Terraform state, so anyone who can read the state bucket can read the key. That's the same people who can already read Secret Manager today, but call it out in the PR.
- Roll out sandbox first. NatCen waits for its post-testing apply.

## Definition of done

- [ ] Each environment's Themes key is generated by Terraform and stored in that project's Secret Manager
- [ ] No two environments share a Themes key (checked by hash)
- [ ] A second plan shows no change to the key
- [ ] Themes UI works after the switch in sandbox, dev and preprod (open it and run a job)
- [ ] Old hand-made `themes_flask_secret_key` deleted from each project
- [ ] Rotation steps written up in the README or runbook
- [ ] Changelogs updated in each environment
